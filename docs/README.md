# Документация разработчика

taskMaster сейчас выпускается для Windows. Здесь описаны устройство приложения, путь от идеи до PR и отправные точки для портирования. Поддержка Linux и macOS пока не подтверждена нативными проверками и не включена в CI.

| Задача | С чего начать |
| --- | --- |
| Запустить проект и выбрать проверки | [Окружение и команды](DEVELOPMENT.md) |
| Найти место для изменения | [Архитектура, IPC и данные](ARCHITECTURE.md) |
| Разработать свою фичу | [Руководство по добавлению фичи](ADDING_FEATURES.md) |
| Собрать на Linux или macOS | [Сборка и портирование](PORTING.md) |
| Уточнить существующие продуктовые правила | [Поведение приложения](BEHAVIOR.md) |
| Изменить оформление или доступность | [Визуальная система](../DESIGN.md) |
| Отправить вклад | [CONTRIBUTING](../CONTRIBUTING.md) |
| Работать через AI-агента | [AGENTS](../AGENTS.md) и [.agents/skills](../.agents/skills) |

Для первого изменения: запустите проект по `DEVELOPMENT.md`, найдите похожую операцию по `ARCHITECTURE.md`, затем пройдите сценарий из `ADDING_FEATURES.md`. Для переноса начните с ограничений в `PORTING.md`, прежде чем менять общие модули.

## Где поддерживать информацию

`README.md` остаётся короткой пользовательской страницей. Продуктовые правила принадлежат `BEHAVIOR.md`, устройство кода — `ARCHITECTURE.md`, команды — `DEVELOPMENT.md`, платформенные различия — `PORTING.md`. Общие правила участия находятся в `CONTRIBUTING.md`, обязательный цикл работы агента — в `AGENTS.md`. Не копируйте один справочник в другой: добавляйте ссылку на источник.

После завершения фичи документация должна описывать итоговое поведение, включая ошибки и ограничения. Для новой страницы добавляйте ссылку в эту таблицу. Подробный порядок завершения — в [руководстве по фичам](ADDING_FEATURES.md#завершение-фичи). Агент выполняет этот шаг с навыком [$taskmaster-docs](../.agents/skills/taskmaster-docs/SKILL.md).
